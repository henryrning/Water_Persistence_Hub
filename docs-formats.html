Data formats

What you get in each download and how to read it. This page and the README inside every ZIP are generated from the same source.

What’s in the ZIP

Every download is one ZIP archive. It always contains:

FileFormatPurpose
README.txtTextThis page, plus your selection restated, so the package describes itself.
manifest.csvCSVEvery file in the package with its size and SHA-256 checksum.
TERMS.txtTextThe Terms of Use version that applied when the package was made.
WPH_…​.tifGeoTIFFOne raster per county you selected.

File naming

You never need to build a file name — the download page does it. This is how to decode one:

Raster specification

FormatGeoTIFF, DEFLATE compression
Data type8-bit unsigned integer (uint8)
Coordinate systemWGS 84 / UTM, the county’s native zone (Ramsey: EPSG:32614, UTM 14N)
Resolution3 m × 3 m
ExtentCounty bounding box (Ramsey: 22,491 × 23,340 pixels)
Nodata255
Source imageryPlanetScope daily observations, mid-March to late June

Pixel values

ValueMeaning
1Standing water. The pixel was labelled water in more than the cutoff share of its valid (clear) observations.
0Did not pass the cutoff. It may still have held water briefly.
255Nodata — outside the county or no valid observation.

How the cutoff is applied

Each cutoff is a separate file. The higher the cutoff, the longer water had to stand, so fewer pixels qualify. In Ramsey County, 2025:

CutoffRule for value 1Water areaShare of valid pixels
P70Water in > 70% of valid observations510.7 km²15.2%
P80Water in > 80% of valid observations501.4 km²14.9%
P90Water in > 90% of valid observations489.0 km²14.5%

All three cutoffs share the same grid, projection and encoding, so they can be compared pixel by pixel.

How the layer was produced

Daily satellite images across the planting window are screened for standing water. Each 3 m pixel is labelled water or dry on every clear day. The share of clear days labelled water is compared with the cutoff to produce the final 0/1 mask. See Cautions & accuracy for validation results.

Scripted access

For repeat seasonal pulls, request the same packages the download page builds. Get a personal token from My downloads.

# 1. Request a package
curl -X POST -H "Authorization: Token $WPH_TOKEN" \
  "https://waterhub.illinois.edu/api/v1/packages?counties=38071&year=2025&window=full&cutoff=80"

# 2. Poll until "status": "ready", then download "download_url"
curl -H "Authorization: Token $WPH_TOKEN" https://waterhub.illinois.edu/api/v1/packages/<id>
ParameterValues
countiesComma-separated FIPS codes, or state=ND for every covered county
yearA published year, e.g. 2025
windowfull (only option in the beta)
cutoff70, 80 or 90
